# CodePrism

Pack your codebase into a single, AI-ready Markdown context file — right from
VS Code. CodePrism is a deterministic, gitignore-aware context packer: text
files are included **verbatim** within the size limit, binary assets are
inventoried (path, size, type) instead of dumped, and the output is stable
across runs so LLM prompt caches stay warm.

**100% local packing.** The extension itself makes no network requests — no
LLM API calls, no telemetry, no secret scanning. Your code never leaves your
machine through CodePrism (VS Code's own services and other extensions are
outside its control).

## Features

- **One-click workspace packing** — generates `codeprism-context.md` and opens
  it in an editor tab.
- **Explorer context menu** — right-click a folder, or multi-select any mix of
  files and folders, then *Pack Selected to Markdown* or *Copy Selected as
  Markdown to Clipboard*. Clipboard writes use the VS Code clipboard API, so
  they also work over Remote-SSH / WSL / DevContainers (no `xclip`/`xsel`
  needed on the remote host).
- **Editor title bar refresh** — a refresh button appears on generated context
  documents to re-pack with one click.
- **Nested `.gitignore` support** — root and subdirectory `.gitignore` files,
  negation rules (`!pattern`) and Git repository ancestor rules are honoured
  via `pathspec`. `.git/`, `node_modules/`, build output and caches are ignored
  by default; dependency lock files are ignored unless you opt in. Priority,
  highest first: hard invariants (`.git`, CodePrism's own output), your
  `additionalIgnorePatterns`, the `.gitignore` stack (deeper wins), defaults.
  Explicitly selected files respect ignore rules too (skipped with a warning),
  and nested repositories inside the selection are skipped — pack them
  separately.
- **Binary asset inventory** — images, fonts, audio/video, archives and other
  non-text files appear in the file tree and an asset table with extension,
  human-readable size and type (e.g. `Image/PNG`). Classification runs in a
  fixed order: a known binary extension wins immediately (a text-looking
  `.png` is inventoried without sniffing its body), then a 512-byte content
  sniff, then a NUL byte anywhere in the read content. Extension-first is a
  deliberate design change and an explicit product limitation (no disable
  switch or forced-text mode). Binary bytes are never included.
- **Licence & size preview truncation** — `LICENSE`/`COPYING`-like files and
  text files above `codeprism.maxFileBytes` (default 1 MiB) stay in the tree
  but render only a configurable character preview plus a truncation notice,
  keeping legal boilerplate and giant blobs out of your prompt budget.
- **Safe output** — existing files that CodePrism did not generate are never
  overwritten silently (CLI: `--force`; extension: modal confirmation).
  "Generated by CodePrism" is a heuristic: a `# CodePrism Context:` prefix in
  the first 64 bytes, so a foreign file starting with that header is treated
  as a previous document. A symlink at the output path is replaced itself,
  never written through to its target. Only the *current* `outputFileName`
  self-excludes: a document generated earlier under a different name is an
  ordinary file and may be re-packed.
- **Escape-proof Markdown** — code fences are dynamically sized (`N+1`
  backticks) so files containing their own Markdown fences render correctly.
- **Zero-config runtime** — the Python engine and its pure-Python dependencies
  ship inside the extension. Any Python 3.10+ on your machine is enough; no
  `pip install` required.
- **Status bar + progress notifications** with cancel support, and an output
  channel for diagnostics.

## Requirements

- VS Code 1.85 or newer.
- Python **3.10+** available on PATH (or via the Microsoft Python extension's
  active environment, or `codeprism.pythonPath`).

## Usage

| Entry point | How |
| :--- | :--- |
| Whole workspace | Command Palette → `CodePrism: Pack Entire Workspace to Markdown` |
| Selection | Explorer right-click (single or multi-select) → `CodePrism: Pack Selected to Markdown` / `CodePrism: Copy Selected as Markdown to Clipboard` |
| Refresh | Refresh icon in the editor title bar of a generated context document |

The generated document contains four sections: **Summary** (file/char/line
counts), **File Tree** (box-drawing tree with non-text annotations), **Non-Text
Files** (asset inventory table) and **Text Files Content** (source of every
text file in language-tagged fences; LICENSE-like and oversized files render
a leading preview with an explicit truncation notice).

## Extension Settings

| Setting | Default | Description |
| :--- | :--- | :--- |
| `codeprism.outputFileName` | `codeprism-context.md` | Name of the generated file (written to the workspace root). |
| `codeprism.copyToClipboardAfterGenerate` | `false` | Also copy the Markdown to the system clipboard after writing the file. |
| `codeprism.additionalIgnorePatterns` | `[]` | Extra gitignore-style patterns, e.g. `["*.log", "docs/**"]`. |
| `codeprism.ignoreLockFiles` | `true` | Ignore dependency lock files (package-lock.json, yarn.lock, Cargo.lock, ...). |
| `codeprism.truncateContentPatterns` | `[]` | Extra patterns whose content is preview-truncated (added to the built-in LICENSE/COPYING list). |
| `codeprism.truncatedPreviewChars` | `200` | Characters kept for truncated/size-limited files; `0` omits content entirely. |
| `codeprism.maxFileBytes` | `1048576` | Text files above this size are preview-only (never read in full); `0` disables the limit. |
| `codeprism.pythonPath` | `""` | Path to a Python 3.10+ interpreter executable (no command-line arguments; for wrappers like `py -3` point at the real `python.exe`). Empty = auto-detect. Workspace-level overrides are honoured, so only open trusted folders (the setting can point at any executable). |

## How it works

The extension spawns the bundled Python engine (`bundled/run_codeprism.py`)
with vendored copies of `pathspec`, `binaryornot`, `chardet`, `click` and
`pyperclip`. Arguments are passed as an array (no shell interpolation). In
file mode the engine writes the document and returns a single JSON stats line
on stdout; in clipboard mode it buffers the Markdown and writes it to stdout
in one pass (stats on stderr), and the extension places it on the system
clipboard via `vscode.env.clipboard` — no temporary files, no platform
clipboard utilities. Progress/cancellation are wired through
`vscode.window.withProgress`.

Operational details worth knowing:

- Clipboard mode buffers at most 256 MiB of Markdown (stderr: 16 MiB); beyond
  that the run fails with a clear message instead of growing the extension
  host heap. `copyToClipboardAfterGenerate` applies the same 256 MiB budget
  when re-reading the written file.
- Cancel (or a buffer overflow) kills the whole interpreter process tree,
  with a SIGKILL escalation for wrappers that trap SIGTERM.
- The output directory is created before packing starts, so it exists even
  if the pack later fails.
- The stats JSON is additive-compatible: new fields may appear, existing
  field names and meanings stay stable.

## Privacy

CodePrism performs no network I/O at runtime (building the bundled dependencies
downloads from PyPI/npm); generation is a purely local, deterministic file
walk. There is **no secret scanning**: ensure sensitive files (`.env`, keys,
credentials) are covered by `.gitignore` or `codeprism.additionalIgnorePatterns`
before sharing the document. The Summary section records absolute source
paths, including your user name. Packing is disabled in untrusted workspaces.
